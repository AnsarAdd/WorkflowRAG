# Проверка документа и инкрементальное обновление

Согласовано в разговоре 5 октября: сначала сервер, UI позже. Ветка codex/finch, локальные коммиты; master и remote не изменять. Сохраняем функциональные пакеты, интерфейсы сервисов и реализации в impl.

## Поведение

1. Предпросмотр принимает существующий SourceIngestionRequest либо multipart файл с sourceId и externalDocumentId. Контракт: TXT/Markdown UTF-8, непустой извлекаемый текст, до 10 MiB, ограниченное число секций и чанков. Ошибка контракта прекращает обработку до обращения к модели/поиску и до создания Job.
2. Точное совпадение содержимого с ACTIVE версией того же documentKey возвращает UNCHANGED без поиска и Job. Для изменённого содержимого сохраняется снимок байтов в PostgreSQL на 24 часа. Предпросмотр не создаёт document_version или индекс.
3. Отчёт содержит counts сохранённых/добавленных/удалённых текстовых частей, ограниченную выборку похожих ACTIVE материалов и статус проверки похожести. Полнотекстовый и векторный поиск выполняются параллельно после контракта. Выборка ограничена; отсутствие совпадений не доказывает новизну. Сбой модели даёт явное предупреждение, а не ложный зелёный результат.
4. Подтверждение принимает ID предпросмотра, использует сохранённые байты, проверяет TTL и неизменность исходной ACTIVE версии под блокировкой документа. Изменение базы требует нового предпросмотра (409). Повторное подтверждение возвращает тот же Job; ошибка workflow исправляется существующим retry.
5. Существующий одноступенчатый API сохраняется для автоматизации и проходит тот же контракт. UI и наблюдение за файловой системой не входят в эту доработку.
6. Переиспользование embeddings ищет точный processing fingerprint внутри ACTIVE версии документа независимо от номера и stable_key секции. Модель/revision и фактический текст с контекстом заголовков остаются частью fingerprint. Совпадение по смыслу не основание переиспользовать вектор.
7. Устойчивые чанки: текстовые абзацы не пакуются вместе; переносы/лишние пробелы обычной прозы нормализуются. Слишком длинный абзац делится по предложениям/границам слов. Изменение одного абзаца не сдвигает границы остальных. Форматирование блоков кода сохраняется. Цена: больше небольших чанков, чем раньше; лимит их числа защищает от взрывного роста. Заголовки остаются смысловым контекстом.

## Проверка

Реальный PostgreSQL/pgvector в Testcontainers: снимок неизменен после изменения файла, duplicate confirm, stale/expired preview, отсутствие Job/embedding calls на неверном и неизменном документе, отказ модели виден в отчёте, изменение/перемещение абзаца переиспользует остальные векторы. Полная Maven verify, проверка diff, review, локальный коммит. Старые данные сохраняются; новые правила chunking применяются при следующем обновлении или forceReindex.
